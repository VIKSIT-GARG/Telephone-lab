# Telephone Lab

Trace how fictional public-safety messages mutate through a multilingual telephone chain, inspect critical facts, and select clearer bounded rewrites. Built for Ship Happens / Culture Coded / Trust Issues.

**Research/demo only. Every warning and place here is fictional. This is not an official alert system.**

## Run locally

Requires Python 3.11+ (tested here with 3.12). No Node build is needed.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000. The included recorded mock experiment works immediately. Select **Fresh mock · local API** for a new synthetic run; use **Optimize + hold-out test** for full evaluation. The hosted static version supports replay and export; its live/fresh controls are disabled because Python does not run on that static host. Run the included backend locally for fresh/live work.

For live experiments, set `SARVAM_API_KEY` and `TELEPHONE_ENABLE_LIVE=true` in `.env`, restart, then select Live Sarvam. The key stays server-side and is never included in browser assets or logs. Do not paste keys into chat or browser fields. No live calls were made during the build because a key was not provided. See [verified docs](docs/VERIFIED.md).

The local API is deliberately unauthenticated, bound to loopback, and has no permissive CORS. Do not expose it publicly without adding authentication, quotas and a proper job queue. Full optimization makes many provider calls; start with one trial to smoke-test access, then use 10+ for evaluation. A single process admits one expensive experiment at a time and returns 409 when busy. Do not run multiple workers with this in-process concurrency guard.

## What works

- Three fictional scenarios with explicit ground truth and critical fields.
- Chain A: Hindi → Tamil → Hindi. Held-out chain B: Tamil → Bengali → Marathi → Hindi.
- Each speaker consumes only the previous message. Extraction/judging are separate calls and cannot send truth back to speakers.
- English normalization before extraction; strict fact schema; deterministic date, time and quantity checks; separate semantic judging prompt for fuzzy facts.
- Per-fact preserved/altered/dropped/invented labels, danger flags, mutation spans and full evidence tables.
- Up to four rewrite strategies with character length cap, feedback-driven repetition, early stopping, and a fixed budget. Original remains selected if nothing improves.
- Fresh chain A validation and fresh chain B baseline/optimized evaluations after selection. Hold-out never drives optimization.
- JSON run persistence, failed-run logs, replayable bundled mock experiments, report export, seeds and prompt/response provenance.
- Responsive accessible frontend; methodology and optimizer-decision dialogs.

## Modes and honesty

**Mock** uses a seeded synthetic text-noise simulator. All mock speakers output English renderings. Noise is deliberately lower for labeled messages, so gains are partly built into this simulation. Mock numbers validate plumbing, not multilingual performance or public-safety efficacy.

**Recorded mock** replays the committed `dist/demo.json`; no API calls or fresh generation happen. These records were generated by this implementation, not hand-entered percentages.

**Live** uses the verified Sarvam chat API. Errors, invalid schemas, unsupported evidence, empty responses and truncation are surfaced with no fallback. Run JSON includes mode/provenance. Extraction/judging uses a different prompt, but the same model by default. True independent-model/native-speaker grading remains a limitation.

No Bhojpuri or dialect fidelity is claimed. Optional TTS/STT is omitted. Indian-language quality, real-human drift and alert usefulness need native-speaker studies. Mock extraction is deliberately narrow and handles bundled templates; it is not a general language parser. In live mode a model may still misextract or normalize incorrectly. Numeric checks prevent equivalence guessing, but cannot eliminate upstream translation/extraction errors. The six-field schema captures invented values where the source field is absent; it does not claim to detect every possible new claim outside the schema. Contradictory multiple deadlines also need a richer schema and manual review. An altered critical field is conservatively dangerous even when semantically less severe.

## Metrics

CFS = final-hop preserved critical facts / all critical facts, averaged over N trials. Fact survival counts source-supplied facts per hop. Danger rate = trials with **any** hop containing a critical mutation. Final-hop danger rate is additionally available in JSON. Mutation counts and per-fact counts aggregate all hops, so their denominator is not trials. Every UI percentage shows N. Optimizer training scores are separate from fresh validation scores.

Dates are relative to each scenario's `anchor_date` in 2030, never the machine clock. Length ratio uses Python Unicode character counts, including punctuation/spaces, with the original as denominator. English comparison can underrepresent nuance. Small sample sizes and optimizer selection bias require replication; scores do not imply statistical significance.

## Evaluate and test

```bash
python -m pytest -q
python -m scripts.evaluate --mode mock --trials 10
# After provisioning the key and explicitly enabling live mode:
python -m scripts.evaluate --mode live --trials 10 --output runs/live-evaluation.json
```

The evaluation command processes all three sources; each has N ≥ 10 trials for baseline, validation and hold-out. Regenerating mock records changes UUIDs/timestamps, but seeded synthetic mutation outcomes remain reproducible. The default file is deliberately named/labeled mock. Live evaluation writes a separate file and never overwrites the committed demo unless explicitly directed.

See [evaluation results](docs/EVALUATION.md), [90-second demo](docs/DEMO.md) and [limitations](docs/LIMITATIONS.md).

## API

Swagger documentation: `/docs`. Routes:

| Route | Purpose |
|---|---|
| GET /api/config | Server capability flags (never the key) |
| GET /api/sources | Bundled source messages and facts |
| POST /api/run | Run a baseline chain |
| POST /api/optimize | Select rewrite on A; validate on A and held-out B |
| GET /api/runs | Recent saved IDs and sizes |
| GET /api/runs/{id} | Replay raw saved report or failure |

Example body for `/api/run`: `{"source_id":"flood","mode":"mock","chain":["Hindi","Tamil","Hindi"],"trials":10,"seed":42}`. `/api/optimize` adds `holdout_chain`, `rounds` (1–4), `length_cap` (1–2), and `target` (0–1). JSON files are written atomically to `runs/` (configurable). Input validation rejects invalid languages, empty critical sets, excessive trials and identical train/test chains.

## Layout

```text
app/chain.py           Hop orchestration and metrics
app/extract.py         Normalization, extraction and comparisons
app/optimize.py        Candidate selection and hold-out isolation
app/providers/        Sarvam adapter and explicit synthetic provider
app/main.py            FastAPI routes and file persistence
data/sources.json     Three fictional messages and approved facts
dist/                 Buildless UI and recorded mock report
scripts/evaluate.py   Reproducible all-source experiment command
tests/                Unit, provider and API tests
docs/                 Verification, evaluation, demo and limitations
```

## Container

```bash
docker build -t telephone-lab .
docker run --rm -p 127.0.0.1:8000:8000 --env-file .env -v "$PWD/runs:/app/runs" telephone-lab
```

Docker instructions are supplied but were not executed in the build environment. Keep the host port on loopback. The image runs as an unprivileged user; the mounted runs directory must be writable by UID 10001.
